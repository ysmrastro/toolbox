# 月の満ち欠けシミュレーター

月をドラッグして軌道上を動かすと、北極から見下ろした図（軌道）・地球から見た月の形（見え方）・福岡から南を見た空（地平線ビュー）が同時に変わる。未就学児を含む家族連れ向けのお話会で使うことを想定し、漢字にはふりがなを付けてある（小学3年生までの漢字は漢字＋ルビ、4年生以上はひらがなを基本にしている）。

**実際のこよみ・実際の天文計算を使っている。** 位置・出入りの計算は自前で持たず、`meteor-settings/astro.js`（`MS_ASTRO`。国立天文台の公表値と突き合わせ済み）をそのまま `<script>` で読み込んで使う ── コピーすると二重管理になるため。`meteor-settings/astro.js` の関数を変えたときは、このツールの表示も変わりうる。

## 状態は経過日数ひとつだけ

内部の状態は `app.js` の `simDay`（実数・経過日数）ひとつだけ。`DAY0`（2026-09-11・新月00:50 JSTの日）を基準にする。

- `simDay = 日 + 時刻/24`。「日」つまみ（0〜29の整数）と「時刻」つまみ（0〜24時）は、どちらも `simDay` の別の見方
- `simDay` の整数部がそのままカレンダーの日付になる（`dateForSimDay()`）。`日` つまみの横には `9/26` のように日付を出す
- 初期表示は **2026-09-26 20:00**（お話会の当日・時刻。`simDay = 15 + 20/24`）
- 自動再生は `simDay` を実時間に応じて増やすだけ。速さは「1秒あたり何時間ぶん進めるか」（1／6／24／72 時間）で選ぶ
- 月をドラッグしたときは、つかんだ角度（＝離角）に最も近い時刻を今の日付の前後で探して `simDay` を決める（後述）

観測地は**福岡**（北緯33.59°・東経130.40°）で固定している。

## 月の位置・満ち欠け・月齢

すべて `MS_ASTRO.moonInfo(date, lat, lon)` の実際の値を使う（近似式は使っていない）。

- **月齢**は `moonInfo().age` そのまま。名前（新月・三日月・上弦・満月・下弦）の判定も、朔望月 `SYNODIC = 29.530589` 日を使ってこの実際の値に対して行う（`phaseName()`）
- 軌道上の角度 `phi` は、**実際の離角**（月と太陽の黄経の差。`moonInfo().elongation`）をそのままラジアンにしたもの（`phi = elongation * RAD`）。太陽・地球・月のなす角そのものなので、近似の入る余地がない
- 月は**北極から見て反時計回り**に動く（実際の公転方向と同じ）。`app.js` の `moonPositionOnOrbit()` は
  `x = 中心x - R*cos(phi)`, `y = 中心y + R*sin(phi)` で、`phi=0` が左（新月）、`phi=90°` が下（上弦）、
  `phi=180°` が右（満月）、`phi=270°` が上（下弦）になるように作ってある
- 地球から見た月の形（右のパネル）は、**北半球の観測者から見た形**にしてある（南半球では左右が逆になる）
  - 輝面率は `k = (1 - cos(phi)) / 2`。明暗の境界（ターミネーター）は、月の輪郭（真円の半分）と
    半径 `|r * cos(phi)|` の半楕円を組み合わせて作る（`moonShapePath()`）。三日月〜半月〜満月〜
    有明月のどの形も、この1本の式でつながる
  - 暗い側も `--mp-moon-dark` でうっすら塗っている（地球照を厳密に再現したものではなく、
    「真っ黒にしない」ための見た目上の配慮）

### 月をドラッグしたときの逆算

つかんだ角度から目標の離角を作り（`targetElong = 角度（度）`）、それに実際の離角が一致する時刻を
`findDateForElongation()` で探す。離角はほぼ一定の速さ（`360 / SYNODIC` 度/日）で増え続けるので、
astro.js の `moonAge()`（朔をニュートン法で探す）と同じ要領で、平均の速さを使ったニュートン法を
8回まわせば実用上十分な精度で収束する（厳密な逆算はしていない。指示どおりの簡略化）。

## 日本（自転で向きが変わる）

北極中心の正距方位図法もどき ── 緯度から中心距離、経度から向きを決める簡略な投影。

- **日本の向きは、福岡での太陽の時角**（実際の南中時刻を基準にする）から決める:
  `japanRotDeg(sun, date) = 180 + 太陽の時角`（度・数学座標。反時計回りが正）。
  時角は `gmst(date) + 経度 - 太陽の赤経` から作り、-180〜180 に正規化してある
  （`sunHourAngleDeg()`）。時角0（南中）で日本が画面左（太陽側）、正で午後（西へ）、負で午前（東へ）
  - 以前は `(時刻-12)*15` という近似（均時差も、福岡の経度が日本標準時の基準子午線から
    ずれていることも無視していた）を使っていたが、実際の時角に置き換えた
- 日本の**形**（`JAPAN_LANDMASSES`。北海道・本州・四国・九州を別々の多角形にしてある）は、
  実際の経度差（東経130〜145°）をそのまま角度のずれとして使う ── `projectLonLat()` は
  `角度 = japanRotDeg(...) + (経度 - 135)`、`中心からの距離 = EARTH_R * (90 - 緯度) / 90`
  で1点ずつ投影する
- ただし正しい縮尺のままだと、この絵の地球（半径 `EARTH_R`）の上では日本が数px の
  点にしかならず、列島の弧が見えない。**代表地点（東経135°・北緯36°）からの緯度経度の
  ずれだけを `JAPAN_SCALE` 倍に誇張して**、列島の弧の長さ（北海道の北端〜九州の南端）が
  地球の半径のおよそ0.8倍になるようにしてある（`projectJapan()`）。この倍率でも
  最遠点の中心距離は `EARTH_R` より内側に収まっている。地平線の接線・人の印も、この
  誇張後の代表地点に合わせて置いている（判定の計算そのものは角度だけを使うので、
  誇張しても結果は変わらない）
- 塗りは gold（`--mp-gold`）、縁取りはそれより暗い色（`--mp-gold-edge`）にして、
  島どうしの境目が分かるようにしている
- 海岸線データを持っていないので、**大陸は描いていない**（形が不正確なまま大陸まで描くと、
  日本との位置関係が余計に不正確に見えるため）

## 昼夜・月の出没の判定

**太陽・月の実際の高度**を、日の出入りと同じ基準で見る（`isDaytimeAt()` / `isMoonUpAt()`）。

- 昼夜: 太陽の高度 `> -0.833°`（`SUN_HORIZON_ALT`。上辺が地平線に接する＝大気差込み）なら昼
- 月の出没: 月の高度 `> 0.125°`（`MOON_HORIZON_ALT`。地心高度。視差・大気差・視半径の合成）
  なら「出ている」

この2つのしきい値は `astro.js` の `dayEvents()` / `nightTimeline()` が内部で使っている
`SUN_HORIZON` / `MOON_HORIZON` と同じ値を、コピーではなく同じ数値として持たせてある
（astro.js側がこの値を変えたら、ここも合わせて見直す）。月が沈んでいる（`isMoonUpAt()` が
false）ときは、右の「地球から見た月の形」パネルにオーバーレイを重ねて暗くし、見えないことを示す。

## 地平線ビュー（福岡から南を見た空）

3枚目の図。正距円筒（方位・高度をそのまま x・y にする素朴な投影）。

- **視野は方位90°(東)〜270°(西)の180°。** 最初はユーザーの要望どおり120°で試したが、
  それだと真東・真西が視野に入らず日の出入り・月の出入りが見えないため、180°に広げた。
  左が東、中央が南、右が西（南を向いて立った見え方）
- 縦は高度0°〜90°をそのまま y にする（正距円筒）。地面（暗い帯）の境界が高度0°＝地平線
- **空の色**は太陽の高度から**縦のグラデーション**（上＝天頂側／下＝地平線近く）で作る
  （`skyGradientColors()`。SVG の `linearGradient` を使い、`objectBoundingBox` 既定のまま
  なので、地平線ビューの縦横比が変わっても比率は自動で合う）。単色だと、夕方でも
  「灰色がかったピンク一色」になって夕方らしく見えない不具合があったため、上下2色を
  太陽高度ごとに持たせている:
  - 高度 -18°（天文薄明＝夜）: 上下とも `rgb(11,16,30)` の紺で一様
  - 高度 -4°（この下は薄明）: 上は紺寄り `rgb(20,26,50)`、地平線近くはわずかに色が残る
    `rgb(120,80,95)`
  - 高度 0°（日の出入り）: 上は青〜群青 `rgb(45,55,115)`、地平線近くはいちばん焼ける
    オレンジ `rgb(230,120,70)`
  - 高度 +6°（昼の空色に達する）: 上は濃い青 `rgb(30,95,175)`、下は明るい水色
    `rgb(143,205,236)`
  - この4点の間を上下それぞれ線形補間する（`lerpColor()`）。+6°を昼の到達点にしているのは、
    0°ちょうどで色が飛ぶ（不連続に変わる）のを避けるため
  - 太陽の方位側を明るくする演出は、指示で任意とされていたため今回は入れていない
- **太陽・月**は、実際の高度・方位のその位置に描く。視野の外（方位が90〜270の外）や
  地平線の下（高度0以下）にあるときは描かない
- **月の向き**: 明るい側は常に太陽の方向を向く。月の位置から太陽の位置への方向を、
  この投影の x・y 座標の上でそのまま `atan2` で求めて、月のアイコンをその角度だけ回す
  （`moonShapeLocalPath()` は「ローカルの +x側が明るい」形を作り、`rotate()` で向きを付ける）。
  3次元の正しい方向ではなく、あくまでこの投影の上での近似（指示どおり）
- **昼間（太陽の高度>0）は月を半透明**（`opacity:0.4`）にする
- 見かけの大きさ（太陽半径12・月の半径15、viewBox単位）は**誇張してある**（見やすさ優先）
- **月の通り道**は、**「いま」の前後12時間**（10分刻み）の方位・高度を求め、地平線より上・
  視野の中にある区間だけを点線でつなぐ（`computeMoonTrack()` / `trackPathD()`）。
  最初はその日の 0:00〜24:00 で描いていたが、それだと真夜中をまたぐ「いま見えている月の弧」が
  0時の前後でちょうど2つに割れてしまう（0〜3時側は前の晩の弧、21〜24時側は今晩の弧で、
  別の弧なのに隣り合って見えて「途切れている」ように見える不具合があった）。「いま」を
  中心にした窓なら、いま見えている弧はその中に丸ごと収まる
  - 3時間ごとの目盛り（例「18」「21」「0」）もこの±12時間の窓の中で拾う（`updateTicks()`）。
    日付をまたいでも時だけを表示する（「0」「3」のように）
  - 出入りの時刻（`dayEvents()`）は日が変わったときだけ作り直すが、通り道・目盛りは
    「いま」が動くたびに窓自体が動くので、`render()` のたびに作り直している
    （10分刻み×24時間ぶんの評価は軽く、毎フレームでも問題にならない）
- **日の出・日の入り・月の出・月の入り**は `MS_ASTRO.dayEvents(date, lat, lon)` の値をそのまま、
  分まで表示する（出入りが無い日は「なし」）

### viewBox の縦横比は実際のレイアウトに合わせて変える

指示では「2:1くらい」だが、軌道図・月の形と3枚を1280×800に収める都合で、実際に割り当てられる
縦横比は2:1よりずっと横長になる（1280×800で約6:1、1280×720で約8.5:1）。固定の2:1 viewBox の
まま幅いっぱいにすると、高さ基準でしか拡大できず、左右に大きな空白ができてしまう。そこで
`ResizeObserver` でパネルの実際の縦横比を測り、viewBox の高さ（`HZ_H`。幅 `HZ_W=640` は固定）を
その都度作り直している（`resizeHorizon()`）。歪みは出ない（幅・高さの比だけ変えて、月や太陽の
描き方は変えていない）が、画面が縦に狭いほど地平線ビューは横に細長くなる。

## レイアウト（デスクトップで画面の高さいっぱいに広げる）

`body → mp-app → mp-stage → (mp-stage-top | mp-panel--horizon) → svg` と flex を通し、
タイトル・読み取り・操作部の自然な高さを引いた「残り」を図に渡す。

- `body` に `height:100vh` を明示しないと、flex-grow が配る「残り」を計算できない
  （reset.css の `min-height:100vh` だけでは高さがコンテンツ依存のままになる）
- `mp-stage-top`（軌道図・月の形の行）と `mp-panel--horizon` は `flex: 1 1 0` で対等に
  「残り」を分け合う。最初は地平線ビューだけ `aspect-ratio:2/1` で高さを決めようとしたが、
  3枚ぶんの高さがそもそも1280×800に収まらず、上段がほぼ潰れる不具合になったため、対等な
  flex-basis:0 に直した
- svg 自身は `width:100%; height:100%` にするだけでよい。軌道図・月の形は viewBox が
  ほぼ正方形なので、preserveAspectRatio により歪んだり切れたりしない
- 1280×800・1280×720 とも操作部までスクロールなしで収まることを確認している
  （1280×720 は収まらなくてもよい、という指示だったが実際には収まった）

## 実際の暦とは連動する（ただし日は0〜29のループ）

「時刻」は現実の時刻と同じ意味で使っているが、「日」は 0〜29 の30日ぶんをループするだけで、
それを超えて実際のカレンダーが進み続けるわけではない（`DAY0` から最大29日ぶんだけを扱う）。
