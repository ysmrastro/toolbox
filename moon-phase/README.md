# 月の満ち欠けシミュレーター

月をドラッグして軌道上を動かすと、北極から見下ろした図（軌道）と、地球から見た月の形（見え方）が同時に変わる。未就学児を含む家族連れ向けのお話会で使うことを想定し、漢字にはすべてふりがなを付けてある。

## 状態は経過日数ひとつだけ

内部の状態は `app.js` の `simDay`（実数・経過日数）ひとつだけ。0日目の正午を基準にする。

- 「日」つまみ（0〜29の整数）と「時刻」つまみ（0〜24時）は、どちらも `simDay` の
  別の見方を操作しているだけ ── `simDay = 日 + 時刻/24`
- 月をドラッグしたときは、つかんだ角度から `simDay` を逆算して、両方のつまみを
  更新する（`日 = floor(simDay)`、`時刻 = (simDay - 日) * 24`）
- 自動再生は `simDay` を実時間に応じて増やすだけ。速さは「1秒あたり何時間ぶん進めるか」
  （1／6／24／72 時間）で選ぶ

日・時刻の2本のつまみは、内部では**独立した2つの物理**を動かしている。

## 月の満ち欠けのモデル

太陽は地球から見て十分に遠く、光はどの位置でも同じ向き（画面の左から右）で当たるとみなしている。この近似の範囲で、次の3つだけで見え方が決まる。

- **月齢 age**（`simDay` を朔望月 `SYN = 29.5306` 日で割った余り）から、軌道上の角度
  `phi = age / SYN * 2π` を作る（新月＝0）。`日` つまみが 0〜29 まで一周しても、
  月齢は `SYN`（≒29.53日）で別に周期するので、1周ごとに少しずつずれていく
  ── これは実際の暦とカレンダーの日数がずれていくのと同じ現象
- `phi` は同時に、太陽・地球・月のなす角（離角 E）でもある ── 太陽が無限遠にあるとみなしているので、地球から見た太陽の方向は常に一定（画面の左）であり、地球から見た月の方向の角度がそのまま離角になる
- 月は**北極から見て反時計回り**に動く。`app.js` の `moonPosition()` は
  `x = 中心x - R*cos(phi)`, `y = 中心y + R*sin(phi)` で、`phi=0` が左（新月）、
  `phi=90°` が下（上弦）、`phi=180°` が右（満月）、`phi=270°` が上（下弦）になるように作ってある

### 北極から見下ろした図（左）

地球・月とも「太陽側＝左半分が明るい」固定の絵（`halfDiskPath()`）。月はこの絵のまま、軌道上を位置だけ動く。北半球側からの視点を示す印として、地球の中心に北極を表す白い点を置いている。

### 日本（自転で向きが変わる）

北極中心の正距方位図法もどき ── 緯度から中心距離、経度から向きを決める簡略な投影。

- **経度の違いは無視して「日本時間＝日本の地方時」として扱う**（指示どおりの簡略化）。
  回転そのものは、日本の代表子午線（東経135°＝日本標準時の基準）が今何時かだけで決める:
  `japanRotDeg(time) = 180 + (time - 12) * 15`（度・数学座標。反時計回りが正）
  - 正午に 180°（画面左＝太陽側）、18時に 270°（画面下）、0時に 0°（画面右）、
    6時に 90°（画面上）になる。月の公転と同じ反時計回りにしてある
- 日本の**形**（`JAPAN_OUTLINE`、十数点の緯度経度）は、実際の経度差（東経130〜145°）を
  そのまま角度のずれとして使う ── `projectLonLat()` は
  `角度 = japanRotDeg(time) + (経度 - 135)`、`中心からの距離 = EARTH_R * (90 - 緯度) / 90`
  で1点ずつ投影する
- ただし正しい縮尺のままだと、この絵の地球（半径 `EARTH_R`）の上では日本が数px の
  点にしかならず、北海道・本州・九州の見分けがつかない。**代表地点（東経135°・北緯36°）
  からの緯度経度のずれだけを `JAPAN_SCALE` 倍に誇張して**、形だけ見える大きさにしてある。
  代表地点そのものの位置（地平線の接線・人の印）は誇張していない
- 海岸線データを持っていないので、**大陸は描いていない**（形が不正確なまま大陸まで描くと、
  日本との位置関係が余計に不正確に見えるため）

### 昼夜・月の出没の判定

太陽の方向は常に画面左＝ベクトル `(-1, 0)`。日本の方向・月の方向は、それぞれの回転角
（`japanRotDeg(time)` と `phi`）から単位ベクトルを作り、**2つのベクトルのなす角が90°未満
＝内積が正**で判定する（`app.js` の `isDaytimeAt()` / `isMoonUpAt()`）。

- 日本の方向ベクトル: `(cos(rot), -sin(rot))`（`rot` は `japanRotDeg(time)` をラジアンにしたもの）
- 月の方向ベクトル: `(-cos(phi), sin(phi))`
- 昼夜: 太陽方向・日本方向の内積 `-cos(rot) > 0` なら昼
- 月の出没: 月方向・日本方向の内積 `-cos(phi - rot) > 0` なら「出ている」

**緯度・地軸の傾き・月の軌道の傾きはすべて無視している。** 地球の自転軸は地面
（黄道面）に対して傾いており、実際の昼夜の境界や月の出没時刻は季節・緯度で変わるが、
この簡略モデルでは「12時＝正午＝太陽側」「6時と18時が昼夜の境目」という、
赤道上・春分秋分のような対称な状態だけを扱う。月が沈んでいる（`isMoonUpAt()` が false）
ときは、右の「地球から見た月の形」パネルにオーバーレイを重ねて暗くし、見えないことを示す。

### 地球から見た月の形（右）

**北半球の観測者から見た形**にしてある（南半球では左右が逆になる）。

- 満ちていく（`phi` が 0〜180°）ときは**右**から光る、欠けていく（180〜360°）ときは**左**から欠けていく
- 輝面率は `k = (1 - cos(phi)) / 2`（新月0・上弦/下弦0.5・満月1）
- 明暗の境界（ターミネーター）は、月の輪郭（真円の半分）と、半径
  `|r * cos(phi)|` の半楕円を組み合わせて作る（`moonShapePath()`）。
  三日月〜半月〜満月〜有明月のどの形も、この1本の式でつながる
- 暗い側も `--mp-moon-dark` でうっすら塗っている（実際の地球照を厳密に再現したものではなく、「真っ黒にしない」ための見た目上の配慮）

### 実際の暦とは連動しない

「日」「時刻」はこのツールの中だけの経過日数・時刻で、実際の日付・現在時刻とは連動していない（スコープ外）。
