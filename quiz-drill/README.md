# 4択ドリル

自分で用意した4択問題のファイル（JSON）を読み込んで、スマホで解いて練習するツール。

- サイト: https://ysmrastro.github.io/toolbox/quiz-drill/
- **アプリには問題が入っていない。** 問題は利用者が読み込み、その端末のブラウザの中（IndexedDB）にだけ保存される。どこにも送信しない
- 見本の問題（`sample.json`、架空の一般常識の問題5問）で動きを試せる

## 使い方

1. 問題ファイルを用意して端末に送る（AirDrop・ファイルアプリなど）
2. ホームの「問題ファイルを読み込む」から選ぶ（複数選択できる）。読み込んだ問題集の一覧は名前順（数字は大きさで並ぶ）
3. 出題方法を選んで「はじめる」
   - **問題集ごとに通し** — 問題集を選び、`no` の順に全問
   - **問題集の中でランダム** — 問題集を選び、全問を無作為な順に
   - **全問題からランダム** — 読み込んだ全問題集から 10 / 30 / 60 / 全部
   - **まだ解いていない問題** — 1回も解いていない問題を、選んだ問題集（または全問題集）から無作為な順に 10 / 30 / 60 / 全部。問題集を足したときや、あとから問題を足したときに、新しい分だけを解ける
   - **模擬試験** — 問題集を1つ選び、本番と同じ形で通しで解く（下の「模擬試験」）
   - **苦手な問題** — 正答率がしきい値（50/70/80%）未満か最後に不正解の問題を、正答率の低い順に。問題集（またはすべて）・出題数を選べる
   - **前に間違えた問題** — 最後に解いたとき不正解だった問題を、選んだ問題集（または全問題集）から無作為な順に 10 / 30 / 60 / 全部。正解すると対象から外れる
   - **絞り込み** — 問題に `tags` があれば「すべて」「〈タグ〉だけ」「〈タグ〉を除く」で絞れる。どの出題方法にも効く。タグの無い問題は「だけ」には入らず、「除く」には入る
   - 今の条件で対象になる問題数をホームに出す。0問なら開始できない
4. 選択肢をタップするとすぐ判定する（選び直しはできない）。回答後に元の番号順の選択肢・解説・補足が出る

- 選択肢は問題を表示するたびに並べ替える（`fixedOrder: true` の問題を除く）。**正解の表示位置は前回その問題を表示したときと必ず変える**（番号で覚えてしまわないように。複数正答の問題は `answers` の先頭の位置を変える）。「続きから」や見返しで同じ表示を描き直すときは並べ替えない
- 途中で閉じても、ホームの「続きから」で同じ問題から再開できる
- 結果画面から、間違えた問題の見返しと「間違えた問題だけもう一度」ができる。学習の記録の書き出しも結果画面からできる（ホームの「記録を書き出す」と同じ）

## 問題ファイルの形式

```json
{
  "format": "yontaku-drill/1",
  "sets": [
    {
      "id": "unique-set-id",
      "title": "問題集の表示名",
      "questions": [
        {
          "id": "q1",
          "no": 1,
          "category": "第3章",
          "tags": ["計算"],
          "points": 2,
          "question": "問題文",
          "choices": ["選択肢1", "選択肢2", "選択肢3", "選択肢4"],
          "answer": 3,
          "answers": [2, 3],
          "explanation": "解説",
          "supplement": "補足",
          "image": "data:image/jpeg;base64,...",
          "imageAlt": "画像の説明",
          "fixedOrder": false
        }
      ]
    }
  ]
}
```

| 項目 | 必須 | 説明 |
|---|---|---|
| `format` | ○ | `"yontaku-drill/1"` 固定 |
| `sets[].id` | ○ | 問題集の一意なID。**同じ id の問題集を読み込むと置き換え、違う id なら追加** |
| `sets[].title` | ○ | 問題集の表示名。問番号の表示（「◯◯ 問5」）にも使う |
| `questions[].id` | ○ | 問題のID（問題集の中で一意） |
| `question` | ○ | 問題文。改行はそのまま表示する |
| `choices` | ○ | 選択肢。2個以上（通常4個） |
| `answer` | △ | 正解の番号。**1 始まり・元の `choices` の順** |
| `answers` | △ | 正解の番号の配列。あれば、そのどれを選んでも正解（複数正答とされた問題用） |
| `no` | | 問番号（整数）。通しの出題順と表示に使う。無ければ配列の順 |
| `category` | | 分類 |
| `tags` | | タグ（文字列の配列）。ホームの「絞り込み」の選択肢になる |
| `points` | | 配点。2 以上なら「2点」のバッジを出す。結果画面の得点は、`points` の無い問題を1点として数える |
| `explanation` | | 解説 |
| `supplement` | | 補足（訂正の説明など）。「補足」の見出しで出す |
| `image` | | 画像。data URL か、相対／絶対 URL |
| `imageAlt` | | 画像の説明（alt） |
| `fixedOrder` | | `true` なら選択肢を並べ替えない（選択肢が画像の中の記号を指す問題など） |

- △: `answer` と `answers` のどちらか一方は必須。両方あれば `answers` を正答として使う
- 1ファイルに複数の問題集を入れてよい。形式に誤りがあるファイルは、どの問題の何が悪いかを表示して保存しない
- 解説が元の番号（①②…）で書かれていても読めるように、回答後は元の番号順の選択肢一覧を出す

## 模擬試験

公式のオンライン受験の練習画面に合わせた、通しの練習。出題方法「模擬試験」で問題集を1つ選んで始める（絞り込みは使わない）。

- 全問を1ページに縦に並べる。上に「解答数 n/60問」と「残り mm:ss」を貼り付けて、スクロールしても見える。残り5分を切ると赤くなる
- 各問に「Q番号」と赤い「未解答」の札、右上に「あとで見直す」の印。選択肢は元の並びのまま。**答えても正誤は出さず、何度でも選び直せる**
- 最後の「確認する」で見直し一覧（番号の格子。赤い枠は未解答、右上の印は「あとで見直す」）。番号をタップするとその問題へ移る。「解答画面に戻る」で元の位置に戻り、「提出する」で終わる
- 制限時間は50分。始めるときに**モード**を選ぶ。**時間切れの扱いは、公式の手引きには書かれていない**ので、どちらも練習用の挙動
  - **リハーサル**（既定）: 本番どおり。0になったら自動で提出する
  - **練習**: 自動で提出しない。0を過ぎても続けられ、時計は「超過 mm:ss」と赤く出る
- ほかの画面へ移っても何も起きない（本番は強制提出になるが、ここでは再現しない）
- 提出すると、一括で採点する。結果の画面に、点数（配点の `points` を使う）・所要時間・未解答の数を出す。解説は、ここで初めて見られる（間違えた問題をタップ）
  - 練習モードでは、**制限時間内の得点**（時間内に選んでいた答えだけ）と**時間外を含めた得点**を並べる。差が、もっと速く解けていれば届いた点数。時間を過ぎてから選んだ・変えた答えは、時間内の得点に数えない
  - 合格ライン（100点満点で70点）との差は、制限時間内の得点で判定する
- 提出した答えは、通常の回答と同じ学習の記録に入る。**未解答の問題も不正解として残る**ので、あとで「前に間違えた問題」で解き直せる
- 解いている間は画面を点けたままにする（Screen Wake Lock。バーに「☀ 画面点灯中」と出る）。別のタブやアプリへ移ると外れ、戻ると取り直す。対応していない端末では何もしない
- 途中でページを閉じても、ホームの「模擬試験の続きから」で戻れる。残り時間は開始時刻から数えるので、閉じている間も減る

## 自作テキスト

公式や単位の換算など、解きながら見返したいことを自分でまとめたテキストファイル（JSON）を読み込んで見られる。問題集とは別のファイルで、出題には使わない。

- ホームの上のタブで「4択ドリル」と「自作テキスト」を切り替える。最後に開いていたタブを覚えておき、次もそのタブから始める
- 「自作テキスト」タブの「テキストファイルを読み込む」から選ぶ（複数選択できる）
- 読み込んだテキストごとにサブタブを作り、選んだテキストの中身をその下に出す。最後に選んでいたテキストを覚えておく
- 中身の先頭に節の目次を出す（節が2つ以上のとき）。タップでその節に飛ぶ
- 保存先は問題集と同じく、その端末のブラウザの中（IndexedDB の store `texts`）。同じ id のテキストを読み込むと置き換え、違う id なら追加
- 学習の記録の書き出しには入らない

```json
{
  "format": "yontaku-text/1",
  "texts": [
    {
      "id": "unique-text-id",
      "title": "テキストの表示名",
      "sections": [
        {
          "title": "節の見出し",
          "note": "節の補足",
          "items": [
            { "term": "1光年", "value": "約9.46×10¹² km", "note": "光速30万km/s × 1年" }
          ]
        }
      ]
    }
  ]
}
```

| 項目 | 必須 | 説明 |
|---|---|---|
| `format` | ○ | `"yontaku-text/1"` 固定 |
| `texts[].id` | ○ | テキストの一意なID |
| `texts[].title` | ○ | テキストの表示名 |
| `sections[].title` | ○ | 節の見出し |
| `sections[].note` | | 節の補足 |
| `items[].term` | ○ | 用語（「1光年」「ケプラーの第3法則」など） |
| `items[].value` | ○ | 値や式。太字で大きく出す |
| `items[].note` | | 補足（覚え方・使い方など） |

## 学習の記録

**1回答えるごとに1件のログ** `{ id, key, at, ok }` を積み上げる。回数・正答率・最後の結果などは、すべてこのログから計算する。

- `id` は端末ごとに固定のランダムな端末ID＋時刻＋連番。2台で衝突しない
- `key` は `問題集id::問題id`、`at` は答えた日時、`ok` は正解なら `true`
- ホームの「学習の記録」に、最後に解いた日時を「この端末」と「ほかの端末から取り込んだ分」に分けて出す（端末は `id` の先頭の端末IDで分かる）。ほかの端末の分が新しければ、その端末で書き出してここに読み込む

### 苦手な問題

「1回以上解いた問題のうち、正答率がしきい値（50% / 70% / 80%、既定 70%）未満か、最後に不正解」を苦手とする。

- 出題順は正答率の低い順。同じなら不正解の回数が多い順、さらに同じなら無作為に並べる
- 「前に間違えた問題」（最後が不正解の問題を無作為な順）とは別に残してある

### 成績の画面

ホームの「学習の記録」→「成績を見る」から開く。次のものを出す（成績の画面の苦手は、しきい値 70% で数える）。

- 全体: 解いた問題数／全問題数、回答の総数、正答率
- 問題集ごと・分類ごと: 解いた数／問題数、正答率、苦手の数
- 苦手な問題（正答率の低い順に最大30問）: タップすると、元の番号の選択肢と解説を見られる

### 問題集ごとに記録を消す

成績の画面の「問題集ごと」のカードにある「この問題集の記録を消す」で消す。消える回答の件数を示して確認する。

- **ログからは消さず、「消去の印」** `{ "id", "kind": "clear", "setId", "at" }` **を足す**（墓標）。ログを消すだけだと、もう一方の端末のファイルを読み込んだときに和集合で戻ってしまうため
- 集計では、その問題集の回答のうち、最新の印の `at` 以前のもの（同時刻を含む）を数えない。印より後の回答はふつうに数える
- 印も書き出し・読み込みの対象なので、もう一方の端末で読み込むとそちらでも消える
- 前回の正解の位置は、その端末の中だけで消す
- 進行中のセッションはそのまま残る（数え方だけが変わる）
- 読み込んでいない問題集は成績の画面に出ないので、消せない

### まぐれ（あとで復習）

正解したときだけ、解説の画面に「まぐれ（あとで復習）」のボタンを出す。押すと、その回答を集計では不正解として数える。たまたま当たった問題が「前に間違えた問題」「苦手な問題」から外れないようにするため。

- **回答の記録は書き換えず、「まぐれの印」** `{ "id", "kind": "lucky", "ref": 回答の id, "on": true, "at" }` **を足す**（消去の印と同じ墓標方式）。回答の `ok` を書き換えても、和集合は id で重複を捨てるので、もう一方の端末に伝わらないため
- もう一度押すと取り消せる（`on: false` の印を足す）。同じ回答の印のうち最新（`at` が同じなら id の大きい方）の `on` を採る
- その問題を離れたあとは操作できない
- 集計では、まぐれとされた回答を不正解として数える。前に間違えた問題・苦手な問題・正答率・成績の画面・書き出しの `summary` はすべて同じ扱いになる。`summary` の `lucky` はまぐれとされた回答の件数
- 不正解の回答に付いた印と、消去の印で除かれた回答に付いた印は何もしない
- セッションの結果でも不正解として数え、「うち まぐれ n問」を添える。成績の画面には、最後の回答がまぐれの問題の数を出す
- 前回の正解の位置には触れない

### 書き出し・読み込み

別の端末（iPhone と iPad など）とやり取りしたり、ブラウザのデータを消したあとに戻したりできる。

- 書き出し:
  - ファイル名は固定の `quiz-drill-記録.json`（保存のたびに置き換えやすい）
  - 共有メニューが使えるブラウザ（iPhone の Safari など）では共有メニューで渡すので、「"ファイル"に保存」で iCloud Drive に置ける。使えないブラウザではダウンロードになる
- **問題文・選択肢・解説は入らない。** 入るのは回答のログ・前回の正解の位置と、分析用の集計（`summary`）だけ
  - 集計には、その問題集を読み込んでいるときだけ問題集の表示名・問番号・分類・タグを添える
  - `summary` は読み込むときに無視する
- 読み込み:
  - **ログは id で和集合を取る。** 2台で解いた記録は合算され、同じファイルを何度読み込んでも増えない
  - 前回の正解の位置は、今の端末に無い問題の分だけ足す
  - 進行中のセッションには触れない
- 旧形式（`yontaku-drill-history/1`、問題ごとの集計だけのもの）も読み込める。下の「移行」と同じ規則でログに変換してから和集合を取る

```json
{
  "format": "yontaku-drill-history/2",
  "exportedAt": "2026-09-27T01:02:03.000Z",
  "log": [
    { "id": "3f9a1c0d5e7b2a44:mfz2k8a1:12", "key": "set-id::q1", "at": "2026-09-20T10:00:00.000Z", "ok": false },
    { "id": "3f9a1c0d5e7b2a44:mfz2k8a1:11", "key": "set-id::q2", "at": "2026-09-19T10:00:00.000Z", "ok": true },
    { "id": "3f9a1c0d5e7b2a44:mfz2k9b0:13", "kind": "clear", "setId": "other-set-id", "at": "2026-09-21T10:00:00.000Z" },
    { "id": "3f9a1c0d5e7b2a44:mfz2kc10:14", "kind": "lucky", "ref": "3f9a1c0d5e7b2a44:mfz2k8a1:11", "on": true, "at": "2026-09-19T10:00:05.000Z" }
  ],
  "positions": { "set-id::q1": 2 },
  "summary": {
    "set-id::q1": { "attempts": 1, "corrects": 0, "wrongs": 1, "lucky": 0, "rate": 0, "last": "wrong",
                    "lastAt": "2026-09-20T10:00:00.000Z", "lastLucky": false,
                    "setTitle": "問題集の表示名", "no": 1, "category": "分類", "tags": ["タグ"] },
    "set-id::q2": { "attempts": 1, "corrects": 0, "wrongs": 1, "lucky": 1, "rate": 0, "last": "wrong",
                    "lastAt": "2026-09-19T10:00:00.000Z", "lastLucky": true,
                    "setTitle": "問題集の表示名", "no": 2 }
  }
}
```

### 移行（以前の成績の記録から）

以前は問題ごとの集計（回数・正解回数・最後の結果・日時）だけを localStorage に持っていた。これが残っていれば、初回起動時にログへ変換する。

- 各問題について、正解 corrects 件と不正解 attempts−corrects 件を作る。日時は lastAt から1秒ずつさかのぼらせ、最後の1件が最後の結果と一致するように置く
- id は `mig:鍵:attempts:corrects:lastAt:連番` と集計の値から決まる形。iPhone と iPad が同じ集計を持っていても、同じ id になって二重にならない
- 変換したあとも古い記録は消さず、移行済みの印を付ける

## 保存

| 何を | どこに | 理由 |
|---|---|---|
| 問題集 | IndexedDB（問題集1つで1レコード） | 画像入りだと数MBになり、localStorage（5MB前後で頭打ち）に入らない |
| 学習の記録（回答のログ） | IndexedDB（回答1件で1レコード） | 1件100バイト前後で、何年も積み上げると数万〜十万件（数MB〜10MB）になりうる。localStorage では上限に近づき、進行中のセッションまで保存できなくなるおそれがある |
| 自作テキスト | IndexedDB（テキスト1つで1レコード） | 問題集と同じ扱いにそろえた |
| 進行中の模擬試験 | localStorage | 答え・印・開始時刻。答えるたびに保存する |
| 進行中のセッション | localStorage | 出題順・現在位置・各問の回答。回答するたびに保存する |
| ホームで最後に開いていたタブ・自作テキストのサブタブ | localStorage | 小さい値なので |
| 前回の正解の表示位置 | localStorage | 問題ごとに、前回表示したときの正解の位置。表示した時点で更新する（回答しなくても次は別の位置になる） |
| 端末ID・連番 | localStorage | 回答の id を作るため |
| 以前の成績の記録 | localStorage | 移行の元。読むだけで、消さずに残してある |
